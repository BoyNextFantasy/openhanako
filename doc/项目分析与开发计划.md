# 项目分析与开发计划

## 项目背景

基于 Pi SDK 做二次开发，构建一个桌面端 coding agent，对标 Codex/Claude Code 的最强模式。

## Pi 项目结构

Pi 是一个 monorepo，核心包：

| 包名 | 作用 |
|------|------|
| `@earendil-works/pi-ai` | LLM 统一 API（调 20+ 家模型） |
| `@earendil-works/pi-agent-core` | Agent 运行时（消息循环、工具执行、状态管理） |
| `@earendil-works/pi-coding-agent` | CLI 产品本身 |
| `@earendil-works/pi-tui` | 终端 UI 库 |

## OpenHanako 的做法

OpenHanako（HanaAgent）把 Pi 当 npm 依赖用，不做 fork：

```
"@mariozechner/pi-coding-agent": "0.70.2"
"@mariozechner/pi-ai": "0.70.5"
```

### 架构分层

```
Electron 桌面 UI (React 19)
  └─ Hono Server (HTTP + WebSocket, 40 路由)
       └─ HanaEngine (薄门面)
            ├─ AgentManager / SessionCoordinator / PluginManager / ...
            ├─ Hub (EventBus / Scheduler / ChannelRouter)
            └─ lib/pi-sdk/ 适配层 ←── 所有 Pi 导入的唯一入口
                 └─ @mariozechner/pi-* (npm)
```

### 适配层 (`lib/pi-sdk/`)

- `index.ts` — 所有 Pi 导入的唯一入口，封装 createAgentSession、工具工厂、ModelRegistry 等
- `session-options.ts` — 本地 Tool[] 转 Pi SDK 的 allowlist + customTools 格式
- `search-tools.ts` — 搜索工具（自实现 ripgrep/fd 执行器，不依赖 Pi 版本）
- `stream-guard.ts` — 流保护（修复 Pi SDK 空工具名 bug）

### OpenHanako 自建的系统

| 系统 | 位置 | 说明 |
|------|------|------|
| 桌面 UI | `desktop/` | Electron + React 19 |
| Server | `server/` | Hono HTTP + WebSocket |
| 多 Agent | `core/agent.ts` + `core/agent-manager.ts` | 每个 Agent 独立文件夹 |
| 记忆系统 | `lib/memory/` | SQLite + FTS5 多级编译管线 |
| 技能系统 | `lib/skills/` + `core/skill-manager.ts` | SKILL.md 标准 |
| 工具系统 | `lib/tools/`（37 文件） | 网页搜索、浏览器、终端、子 agent 等 |
| 沙盒 | `lib/sandbox/`（22 文件） | PathGuard + OS 级隔离 |
| 插件系统 | `core/plugin-manager.ts` + `packages/plugin-sdk/` | 自研插件运行时 |
| 子 Agent | `lib/tools/subagent-tool.ts` | 三种工具 + RunStore + ThreadStore |
| Hub | `hub/` | 心跳、Cron、事件总线、频道/DM 路由 |
| 多平台桥接 | `lib/bridge/` | Telegram/飞书/QQ/微信 |

### OpenHanako 没动的部分

- **不改 Pi SDK 源码**（曾经 patch 过 node_modules，Pi 0.68+ 后改用适配层）
- **不走 Pi 的扩展系统**（自己的 PluginManager 替代）
- **不用 Pi 的 TUI/CLI**（Electron 桌面端替代）

## 开发目标

在 OpenHanako 基础上添加 coding agent 能力，核心差异化：

### 1. 模式切换引擎

| 模式 | 用途 |
|------|------|
| chat | 自由对话 |
| plan | 先分析再行动 |
| build | 专注实现 |
| debug | 调试修复 |

### 2. 子 Agent 管线（Codex 论文的强度模式）

结构化流水线：plan → implement → review → test → fix，各阶段由不同角色的子 agent 执行。

### 3. Benchmark 专项优化

针对 SWE-bench、HumanEval、GPQA 定制 prompt 和 loop 策略。

### 4. 自学习（基于 OpenHanako 已有能力增强）

- 技能自学：GitHub 发现 + 自写 SKILL.md（已有）
- 记忆编译：滚动摘要 → 事实提取 → 长期记忆（已有）
- 错误模式学习：新增

### 5. Loop engineering（延后）

## 实施计划

| 文件 | 改动 |

| 文件 | 改动 |
|------|------|

## 学习入口

建议阅读顺序：
1. `lib/pi-sdk/index.ts` — Pi 给了什么
2. `lib/pi-sdk/session-options.ts` — Pi API 如何适配
3. `core/engine.ts` — 系统骨架
4. `core/agent.ts` — Agent 如何构建
5. `core/session-coordinator.ts` — Session 如何创建
6. `lib/tools/subagent-tool.ts` — 子 agent 如何工作

Pi 源码只需在需要理解某个被封装函数的具体实现时再翻 `node_modules/`。
