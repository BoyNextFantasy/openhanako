## 0. 背景与定位

**比赛**：AI 大模型作品赛，桌面端 AI Agent 赛道。参赛作品名统一 **Satori**（不再使用 Herness / HanaAgent 口径）。

**一句话定位（对外材料与演示统一口径）**：**可治理的自主智能体** —— 记忆编译让它越用越懂你，Heartbeat/Cron 让它主动干活，五层防线（5 档权限模式 + 双模型 AI 安全评审 + OS 级沙箱 + 规则硬拦截 + 用户确认）让用户敢放权。

**竞品对照（差异化的依据，材料可直接引用）**：

| 竞品 | 强项 | 相对空白 |
|---|---|---|
| OpenCode | 终端优先、75+ 供应商、开源生态大 | 无桌面端、无记忆体系、无自主巡检 |
| Claude Code | plan 模式、hooks、生态成熟 | 记忆只是 CLAUDE.md 单文件；无主动行为 |
| Goose (Block) | 桌面端 + MCP 扩展生态 | 无分层记忆、自主性弱、安全治理浅 |
| Hermes Agent (Nous Research) | 长期自主、越跑越懂你（最接近的对手） | 自主行为不在安全围栏内；无 token 台账 |

**Satori 独有组合**：桌面端 + 长期记忆编译体系（SQLite FTS5 分层编译）+ 安全围栏内的自主巡检 + Windows 原生 restricted-token 沙箱 + Bridge 五平台（飞书/微信/TG/钉钉/QQ）远程指挥 + 全链路 token 用量台账。

- `lib/tools/question-tool.ts:5-13` + `QuestionModal.tsx`：结构化提问闭环（已成熟，不动）。

### 改动方案
1. **新工具 `lib/tools/plan-artifact-tool.ts`**，工具名 `plan_submit`，参数 = PlanArtifact v2 JSON。execute：`normalizePlanArtifact` 校验 → 存入会话级 planArtifact 状态（挂在 engine 或 session-coordinator）→ WS 广播 `{ type: 'plan_artifact', sessionId, artifact }` → 返回「计划已提交，等待用户确认」。
2. **权限白名单**：`core/session-permission-mode.ts` PLAN 分支仿 task 白名单（:350-364）放行 `plan_submit`；其余模式按普通副作用判定（auto 走评审、ask 弹确认，可接受）。
3. **prompt 修订**（`core/agent.ts:1443-1468`）：第③步改为「必须调用 plan_submit 工具提交结构化计划」；第④步（task 建树）**删除**——建树改由确认动作自动完成，避免双重建树。保留「确认前不得动手」约束。

5. **前端** `desktop/src/react/components/chat/PlanArtifactCard.tsx`：分区渲染 goal / scope / outOfScope / steps（含 files、acceptance）/ risks / testPlan +「确认并开始执行」按钮 → POST confirm → 卡片状态变「已确认」；`ws-message-handler.ts` 注册 `plan_artifact` / `plan_confirmed` 事件。视觉规格对齐现有卡片体系（角色标签全宽块、18px 徽章），计划卡用 aurora 主题 accent。
