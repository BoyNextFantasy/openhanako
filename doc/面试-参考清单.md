## 三、防穿帮清单（❌ 不能说 → ✅ 替代说法）

1. ❌ "上下文到 85% 触发压缩" → ✅ 触发是距上限剩 1.6 万 token（绝对余量）；85% 是防抖计数和"摘要请求自身超窗"的判断
2. ❌ "token 成本降 60% / 拦截率 95%" 等未测量数字 → ✅ "以行为验收和回归测试为准，没做过成本对照测量"
3. ❌ "压缩会摘要系统指令" → ✅ 恰恰相反：系统指令不进压缩池，压缩后从磁盘重读原文
4. ❌ "修剪会改写会话文件" → ✅ 纯内存操作，磁盘留完整输出供调试回放（刻意设计）
5. ❌ "防抖计数持久化到磁盘" → ✅ 内存态，会话重载归零（刻意：重载后内存压力状况已变）
6. ❌ "用了精确 tokenizer 计数" → ✅ 字符数除以 4 的估算
7. ❌ "记忆用向量库做语义检索" → ✅ "第一版用过、实测召回不准，换成标签+全文"
8. ❌ "删除是物理删除" → ✅ 对话卡片只编辑注入层文本，库里原行保留（避免单条删除接口的复杂度，刻意取舍）
9. ❌ "每天有反思模型整理记忆" → ✅ "定时管线生成滚动摘要、每日提取事实"（反思执行器当前关闭）
10. ❌ "SQLite 全文检索原生支持中文" → ✅ 默认分词器不认中文，应用层两三字组合展开解决
11. ❌ "结构化计划协议已上线运行" → ✅ "协议+测试已完成；已上线的是权限模式、命令白名单、任务树、提问工具，协议接入主链路是下一步"
12. ❌ "计划确认后状态机流转为已确认" → ✅ 没有状态流转，确认 = 用户手动切操作模式
13. ❌ "Compose 有并行调度器" → ✅ 并行来自通用子 Agent 工具，Compose 注入的是工作流技能
14. ❌ "任务树存 SQLite" → ✅ JSON 文件原子写
15. ❌ "任务树 33 个测试" → ✅ 37 个（口头说"三十多个"）
16. ❌ "任务树有会话隔离" → ✅ 已知限制：没有
17. ❌ "提问超时可配置" → ✅ 硬编码 5 分钟；待答表内存态，服务重启即丢
18. ❌ "源码指纹在正式包也生效" → ✅ 仅开发态；打包版按版本号判断
19. ❌ 评测说"通过率 X% / 完整 benchmark / token 指标已采集 / 随机抽题 / 自建题库" → ✅ 单题 1/1、按目录排序取第一题、token 字段空占位、公开题库浅克隆
20. ❌ "心跳检测用户空闲才触发推理" → ✅ 无此门控；独立后台会话 + 笺指纹条件触发是真实机制
21. ❌ "完成过上游特性移植" → ✅ 只讲"做过分叉分析与选型评估"（2026-09-02 真实完成，数据见上表）
22. ❌ "记忆检索改版 / 中文检索修复 / 滚动摘要 / 置顶存储 / 记忆开关是我写的" → ✅ 这些是上游基座自带（fork 点已存在，git 可查）；本地记忆侧真实工作是"对话内记忆动作（置顶/不再记住卡片）"（2026-07-10 提交）。讲系统设计没问题，说"我写的"会被 git log 戳穿
