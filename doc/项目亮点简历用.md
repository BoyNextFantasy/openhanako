> 用途：简历项目经历、面试自我介绍、面试官追问时的展开材料。
> 写法原则：强调“个人开发主力助手”的工程能力，不把它包装成已经大规模生产落地的商业系统。

  \item \textbf{工程质量与评测：}使用 Vitest 建立面向权限、Plan、Task、Compose、Desktop/WebSocket、compaction、sandbox 的回归测试；实现轻量 benchmark adapter，支持拉取/适配公开 Aider Polyglot 题库并运行 verifier，记录 pass rate、耗时、patch stats、prompt size 等指标，为后续量化 Agent 框架能力预留基础

## 三、面试 60 秒讲法

Satori 是我做的一个个人 AI 编程助手，定位类似 Codex 或 Claude Code，但重点不是套一层聊天 UI，而是搭一个能支撑真实代码迭代的 Agent Framework。

底层我用 Pi SDK 做模型与工具调用，再在上层补了 session 生命周期、工具权限、prompt snapshot、runtime skill、Desktop/CLI 同步这些工程模块。它有长期记忆系统，能区分 agent 级记忆和单次会话记忆；有 Plan 模式，把“先规划不动手”做成权限层约束；也有 Compose 模式，把复杂任务组织成 brainstorm、plan、tdd、execute、review、verify 这样的结构化工作流。

安全上我没有只靠 prompt 约束模型，而是做了 auto、ask、operate、read_only、plan 五种权限模式，在工具调用、命令执行、ResourceIO 和沙箱边界统一拦截。后面我还补了上下文压缩、task tree、子 agent 复审和轻量 benchmark，希望这个项目不是玩具 demo，而是一个可以长期迭代的个人开发主力助手。

## 四、面试官追问口径

### 1. 这个项目和普通 LLM Wrapper 的区别是什么？

普通 wrapper 主要解决“怎么把消息发给模型”。Satori 重点解决的是“Agent 如何可靠参与长任务开发”：会话如何恢复，工具权限如何拦截，长期记忆如何不污染当前任务，压缩后如何不丢上下文，规划阶段如何保证无副作用，复杂任务如何组织成可追踪流程。

### 2. 为什么 Plan 要做成权限模式？

因为只靠 prompt 写“请先不要改代码”不可靠。Plan 模式作为 permission mode 后，写文件、执行副作用命令、推进任务状态这些动作会在工具层被拦截。这样用户在规划阶段可以放心让 Agent 读代码、提问、输出计划和任务树，而不用担心它偷偷动手。

### 3. Compose 和 Plan 有什么区别？

Plan 管“能不能执行”，Compose 管“怎么组织任务”。

Plan 是安全边界，强调先规划、等确认、无副作用。Compose 是工作流方法，强调复杂任务要按澄清、计划、TDD、执行、复审、验收推进。Compose 不会绕过权限，所以 `Ask + Compose`、`Auto + Compose` 这类组合都成立；Plan 下 v1 会强制 Compose 不生效，避免两个工作流提示冲突。

### 4. Compose 和直接加载 Superpower Skills 有什么区别？

直接把 Superpower Skills 永久塞进 agent，只是静态 prompt 增强。Compose 是显式 session workflow state：前端有按钮，后端会持久化，WebSocket 会同步，runtime skill 列表会按状态过滤，prompt 会按 effective mode 注入。

这样普通任务不会被复杂流程污染，用户也不用换 agent 人格；权限模式仍然独立存在，后端还能强制处理 Plan 与 Compose 的冲突。它更像产品里的“工作流模式”，不是一段常驻提示词。

### 5. 记忆系统怎么避免污染？

我把记忆分成 agent 级长期记忆、session 级开关、置顶记忆、会话摘要和当前上下文几个层级。临时任务状态不应该直接变成长期事实，session 关闭记忆时也不能污染 agent master prompt。记忆注入时还要控制存在感：它应该影响模型判断，而不是让模型频繁说“我记得”。

### 6. 权限和沙箱主要解决什么风险？

Coding agent 会直接接触用户本机文件、shell、git、依赖安装和外部应用，所以风险不只是“回答错了”，而是可能真的改坏文件或执行危险命令。Satori 把权限判断放在工具和 resource 边界：不同 session permission mode 下，工具动作会被分类为 allow、prompt 或 deny；Windows 下还特别处理 PowerShell/cmd、路径、递归删除、写入范围和沙箱 helper。

## 五、可以量化的表述

目前可以比较稳地写：

- 支持 5 种 session permission mode：`auto`、`ask`、`operate`、`read_only`、`plan`。
- Plan Artifact v2 包含 6 类核心字段：`goal`、`scope`、`steps`、`risks`、`testPlan`、`confirmationPoints`。
- Compose v1 包含 6 个内置 workflow skills：`brainstorm`、`plan`、`tdd`、`execute`、`review`、`verify`。
- Task 工具支持树形任务 ID 和完整生命周期：`create/list/get/start/block/unblock/done/abandon/rename`。
- 评测系统已能接入公开 Aider Polyglot benchmark，并输出 pass rate、耗时、patch stats、prompt size 等结果。
- 测试覆盖重点模块：权限、Plan、Task、Compose、session 恢复、WebSocket 同步、compaction、sandbox。

暂时不建议在简历里写过强的线上指标，比如“大幅提升效率”“生产可用率 xx%”，除非后续你真的跑出稳定 benchmark 或自己长期使用数据。
