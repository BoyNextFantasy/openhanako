### 迭代方向详情

#### 方向 1：Plan 工作流（先规划再执行）

> **定位**：这不是新的权限模式，而是在现有 auto/operate/ask 模式上附加的**临时工作流步骤**。
>
> 参照：Codex CLI 的 `/plan` 命令、OpenCode 的 Plan agent（Tab 切换）、Hermes Agent 的 plan skill
>
> **与本项目 4 种模式的关系**：
> ```
> auto  + plan → plan 阶段（只读）→ 确认 → 退出 plan → auto 执行
> operate + plan → plan 阶段（只读）→ 确认 → 退出 plan → operate 执行
> ask  + plan → plan 阶段（只读）→ 确认 → 退出 plan → ask 执行（逐个问）
> read_only + plan → 不适用（已是只读）
> ```
> Plan 阶段统一拦截副作用工具，**确认执行后退出 plan phase，回到用户当前所选模式**。

- **已有**：
  - `read_only` 权限模式拦截逻辑（可复用为 plan 阶段的工具限制）
  - `classifySessionPermission()` 的 `INFORMATION_TOOLS` 分类（可直接复用）
  - `SESSION_PERMISSION_MODES` 枚举（auto/operate/ask/read_only）**不新增**
  - `buildSystemPrompt()` 支持条件注入（已有 `forSubagent` 先例，可加 `forPlan`）
  - `context` 参数传递到 `classifySessionPermission`（已有 `isSubagent` 等字段，可加 `phase: "planning"`）
  - Desktop 前端已有会话入口、设置面板（可加 toggle）
- **缺陷**：
  - `read_only` 没有 plan 阶段的 system prompt 引导
  - `read_only` 不允许任何 write 调用（但 plan 也不需要写文件）
  - 无 `/plan` 命令、无 Desktop toggle、无 plan 状态管理
  - agent 判断力不足：没有 prompt 告诉它"什么时候该规划、什么时候不该"

##### 设计方案（已确认）

**核心原则：**
- Plan 是**临时阶段（phase）**，不改变 session 的 `permissionMode`
- Plan 内容在**对话历史里**，不写磁盘
- Plan 阶段**不执行**任何副作用工具（INFORMATION_TOOLS 只读）
- Toggle 只影响**下一条消息**，不干预进行中的 plan

**触发方式：**

| 入口 | Desktop 端 | CLI 端（一期暂不实现） |
|------|-----------|-------------------|
| Toggle 图标 | ✅ 勾选后，agent 可在需要时自动走 plan | — |
| 显式触发 | — | `/plan` 命令 |

**Agent 判断引导：**（通过 system prompt 注入一段指引）
```
When you receive a task that involves multi-file changes, architectural decisions,
or significant uncertainty, you may choose to first output a plan.
- If the task is underspecified, ask 1-3 clarifying questions first.
- After clarifying, output a structured plan (steps, files, risks).
- Then ask "Would you like to execute this plan, or would you like to refine it?"
- Simple questions should be answered directly without planning.
```

**Plan 阶段工具限制：**
- 允许：INFORMATION_TOOLS 全量（read/grep/find/ls/web_search/web_fetch/current_status/search_memory/recall_experience）
- 允许：agent 在对话中输出文本（无需任何工具）
- 禁止：write / edit / bash / subagent / 所有 SIDE_EFFECT_TOOLS
- Plan 阶段不写文件，所有内容在会话文本中

**完整流程：**
```
用户发消息（或 Desktop toggle 勾选 + 已收到消息）
  ↓
agent.ts 检查 context.phase === "planning"
  ↓
是 → buildSystemPrompt() 注入 plan 行为指引
    → 工具拦截层读 phase，放行 INFORMATION_TOOLS，拦其余
    → （可选）agent 提 1-3 个问题澄清需求 ← 用户补充/完善
    → agent 输出 plan 大纲（结构化文本，在对话中）
    → agent 问"按这个执行吗？"
         ├→ 选项 1：确认执行 → 退出 plan → 原始模式按大纲执行
         ├→ 选项 2：补充 → 用户继续输入 → 回退到"提问题/完善大纲"环节
         └→ ESC → 中断 plan，退出 plan phase，不做任何事
  ↓
否 → 走现有 auto/operate/ask 逻辑
```

> 注意顺序：先**提问完善** → 再**输出大纲** → 最后**问是否执行**。不是先输出再提问。

**toggle 开关语义：**
- 勾选（plan 图标亮）= "下一条消息可能走 plan"
- 不勾选 = "不走 plan（除非显式触发）"
- 关掉 toggle **不影响正在进行的 plan**（当前 plan 正常完成并问是否执行）
- Toggle 只在**发送消息前**检查一次

##### 设计方案（已确认）

**核心架构（仿 OpenCode）：**

```
LLM 调 question 工具
  → QuestionService.ask(questions)
    创建 Deferred，await 挂起
    → onUpdate 发 { type: "question", id, questions } → WS → Desktop
      → QuestionModal 弹窗，用户点选/输入
    → WS 收 { type: "question-reply", id, answers }
  → QuestionService.reply(id, answers)
    → Deferred resolve → 工具返回结果 → LLM 继续
```

**工具参数（LLM 视角）：**
```typescript
{
  questions: [{
    question: string,        // 完整问题
    header: string,          // 短标签（≤30 字符）
    options: [{              // 选项列表
      label: string,         // 显示文本（1-5 词）
      description: string    // 选项说明
    }],
    multiple?: boolean       // 允许多选（默认 false）
  }]
}
// 返回：answers: string[][] — 每个问题对应的选中 label 数组
```

**注意：** OpenCode 的 `custom` 参数（允许用户输入自定义答案）一期不实现。只有预设选项。

**服务层 — `lib/question/service.ts`：**
- `interface QuestionService`:
  - `ask(questions)` → `Promise<Answer[]>` — 创建 Deferred，存入 pending map，阻塞等待
  - `reply(id, answers)` — 从 pending map 中 resolve 对应 Deferred
  - `reject(id)` — reject 对应 Deferred（用户关闭弹窗）
  - `list()` — 列出所有 pending 中的问题
- 状态管理：`Map<QuestionID, { questions, deferred: { resolve, reject }, status }>`

**工具层 — `lib/tools/question-tool.ts`：**
- 工厂函数 `createQuestionTool({ questionService })`
- 工具名：`question`，归类：`STANDARD_TOOL_NAMES`
- `execute()` 内调 `questionService.ask()` → await 挂起
- 通过 `onUpdate` 把问题推送到客户端
- 返回结构化 output（含用户答案 + metadata）

**Desktop 端 — `QuestionModal.tsx`：**
- 监听 WS 的 `question` 事件 → 弹 Modal
- 显示选项列表，用户点选
- 支持单选/多选
- 关闭（×）视为 reject
- 用户点选后 → WS 发 `question-reply` → 关闭弹窗 → Deferred resolve → LLM 继续
