## 模块一：`core/media/`

### 这是什么
图片/视频/Audio 媒体生成编排层。`UniversalMediaManager` 管理：
- 图片生成（text2image、image2image）
- 视频生成（text2video、image2video）
- 音频转录（转发给 speech-recognition）
- 插件 adapter 注册、TaskStore 持久化、Poller 轮询
- 内置插件 `image-gen` 和 `media` 依赖它

### 用户能感觉到什么变化
- **AI 工具层面**：`generate_image`、`generate_video`、`describe-options` 工具会失效
- **CLI 核心**：核心对话链不需要它，但如果 AI 被要求 "画图" 会报错
- **Desktop**：MediaTab（图片/视频生成设置页）、AssistantMessage（媒体生成卡片渲染）、MediaViewer（全屏查看）都依赖它

### Desktop 需要改什么

| `desktop/.../MediaTab.tsx` | 调 `/api/media/image/providers`、`/api/media/video/providers` → 会 404，需要条件化隐藏 |
| `desktop/.../MediaProviderDetail.tsx` | 同上 |
| `desktop/.../AssistantMessage.tsx` | 渲染 `media_generation` 块 → 不再出现 |
| `desktop/.../use-stream-buffer.ts` | 处理 `media_generation` 类型 → 需要条件化 |
| `desktop/.../MediaViewer/` | 只查看已有图片，核心不需要动 |
| `desktop/.../MediaTab.test.tsx` | 测试需要修改 |
| `desktop/.../MediaProviderDetail.test.tsx` | 测试需要修改 |
| `desktop/.../AssistantMessage.media-generation.test.tsx` | 测试需要修改 |

## 模块二：`core/speech-recognition/`

### 这是什么
自动语音识别（ASR）系统。将桌面端上传或录制的音频文件转写为文本。包含：
- `SpeechRecognitionService` — 编排层，管理 adapter 注册、transcribe 流程
- 4 个内置 adapter（OpenAI Whisper、MiMo、DashScope Qwen ASR、Volcengine BigASR）
- 支持 `voice-input` 附件自动转写（桌面端语音输入条）

### 用户能感觉到什么变化
- **Desktop**：语音输入条不再自动转写为文字（录音文件仍可发送，但不会自动转文本）
- **API**：`POST /api/media/asr/transcribe` 和 `POST /api/speech-recognition/config` 不再可用
- **Desktop 设置**：MediaTab 中的"语音识别"部分（启用/关闭、选择默认模型）会失效
- **CLI 核心**：完全不受影响

### Desktop 需要改什么
| 文件 | 改动 |
|------|------|
| `desktop/.../MediaTab.tsx` | 渲染"语音识别"区域并调 `/api/speech-recognition/providers` → 需要条件化隐藏 |
| `desktop/.../settings/store.ts` | `speechRecognition` store 字段不再更新 |
| `desktop/.../MediaTab.test.tsx` | 测试覆盖 speech 部分需修改 |

### 相关测试文件及其测试方法

## ~~模块三：`lib/channels/`~~ ✅ 已完成

### 这是什么
多 Agent 群聊系统。Agent 之间可以创建频道、发消息、@提及，支持轮询投递和 phone session 打断回复。
- `channel-store.ts` — 基于 markdown 文件的消息持久化
- `channel-ticker.ts` — 轮询调度引擎，有新消息时投递给 Agent 的 phone session
- `channel-mentions.ts` — @提及解析引擎
- `ChannelManager` — 频道 CRUD 生命周期
- `ChannelRouter` / `DmRouter` — 通过 Hub 连接：phone delivery、回复工具、记忆摘要

**执行情况：** 66 文件，~14k 行已删除。详见 `docs/迭代记录.md`

## 模块四：`lib/bridge/`

### 这是什么
多平台 IM 集成层。用户可以通过 Telegram、微信、飞书、钉钉、QQ 与 AI Agent 聊天。
- `bridge-manager.ts`（~2850 行）— 核心编排器：adapter 生命周期、消息路由、媒体传输
- 5 个平台 adapter：Telegram、飞书、钉钉、QQ、微信
- `core/bridge-session-manager.ts`（~1700 行）— 持久化层：会话索引 JSONL 文件、executeExternalMessage、guest/owner 模式
- 媒体处理子模块：media-capabilities、media-delivery-service、media-item-normalizer、media-publisher、media-roots、media-utils

### 用户能感觉到什么变化
- **外部 IM**：通过 Telegram/微信等外部平台与 Agent 对话的功能完全消失
- **CLI 核心**：完全不受影响
- **Desktop**：BridgePanel（桥接聊天面板）不再可用、BridgeTab（桥接设置页）不再可用
- **引擎层面**：BridgeSessionManager 不再初始化，bridgeManager 不再设置到 Hub
- **通知系统**：`lib/notifications/notification-service.ts` 不再能通过 bridge 发主动消息

## 模块五：`core/computer-use/`

### 这是什么
桌面 GUI 自动化子系统（类比 Anthropic Computer Use）。AI 可以控制用户桌面的原生应用：
- 读取可访问性树（UI Automation / CuaDriver）
- 截图 + 视觉定位
- 点击、输入文字、快捷键、滚动
- 管理窗口：启动、列表、激活
- 支持 macOS（CuaDriver）和 Windows（PowerShell UIAutomation）
- 基于 lease 的互斥访问控制

### 用户能感觉到什么变化
- **AI 工具层面**：`computer` 工具不再可用。AI 不再能说"让我打开计算器"等
- **CLI 核心**：核心对话链不需要它，工具是条件性添加的
- **system prompt**：agent.ts 中有一段 system prompt 指示 AI 优先用 computer 工具而非 bash → 移除后需要清理
- **Desktop**：ComputerUseOverlay（桌面叠加层：鼠标光标 + 点击动画）不再使用、ComputerUseSection（设置页）不再有效
