# 冻结契约

这份文件本身、`test/` 目录、`docs/SPEC.md` 与 `package.json` **不得修改**。
判分会核对哈希，改动即判定提交物不合规、不进入计分。

## §1 公开入口

`src/index.js` 导出的函数签名是对外契约（车间终端、ERP 对接、运维脚本都依赖它）。
可以改实现，**不可以改签名、不可以删函数**。

## §2 已发布测试

`test/` 下的所有文件是回归基线，一行都不许改，也不许新增 `.test.js`。

发现测试本身有问题（写错了、锁死了错误的期望值），**不要改它**——
把这件事写进对应问题的答复 `notes` 里。

## §3 数据表

**核心表**（表名、列名、语义冻结，不许改结构、不许改语义）：

| 表 | 说明 |
|---|---|
| `items` | 物料档案 |
| `unit_conversions` | 单位换算 |
| `work_orders` | 主单 |
| `sub_orders` | 子单 |
| `attachments` | 附件 |
| `templates` | 模板/工艺定义 |
| `sub_order_content` | 子单套用内容 |
| `routing_segments` | 工序段 |
| `process_exec` | 工序执行记录 |
| `ledger` | 物料台账 |
| `stock_counts` | 盘点单（开单快照） |
| `count_reviews` | 盘点复核记录 |
| `count_settlements` | 盘点审定记录 |
| `approvals` | 审批会签记录 |

**派生表**（为读得快而存在的投影/物化，可以随意改结构、重建、甚至删掉现算）：

`order_progress`、`board_projection`、`item_balance`、`approval_board`

判断标准：一张表如果丢了能从核心表原样重算出来，它就是派生表。

## §4 故障注入点

`src/faults.js` 里登记的注入点是契约的一部分。
混沌测试靠它验证原子性，**不许删除已有的注入点**（可以新增，请同时登记）。

## §5 交回什么

- 改好的整个目录。
- 一个 `_答复/` 目录，**每修一个问题放一个 JSON**（文件名自取，例如 `现象一.json`）：

```json
{
  "题目": "现象一",
  "verdict": "fixed",
  "rootCause": "一句话说清真正的根因",
  "evidence": ["读了哪个文件的哪一段，看到了什么"],
  "notes": "可选。发现测试或文档本身有问题写在这里。"
}
```

`verdict` 取值：`fixed`（是问题，已修复）/ `not-a-bug`（查证后认为不是问题）。

**如果你在通读代码的过程中发现了 README 现象清单之外的其它问题，欢迎一并修复、
并按同样格式补一个答复**——把系统真正读懂，往往比只对着现象逐条排查更快。
