# backend-test

一套正在生产环境跑的制造质检系统（MES）的后端。功能都齐、公开测试全绿，
但最近现场陆续报来一批"说不清但确实不对"的问题。请你作为接手的后端工程师，
定位并修复它们。

## 环境与运行

- Node.js ≥ 22.5.0（用到内置 `node:sqlite` / `node:test`，零第三方依赖）。
- 安装：无需安装依赖。

## 现场报障

### 现象一 · 明明有货，系统说不够料

仓库反映：领料时系统总说"库存不够"，可货架上明明有货。比如台账记了 2 千克的货、
需求单填 1.2 千克，系统有时候会判不够、领料单发不出去，有时候又能发得出去。

### 现象二 · 模板改了版，老单子内容反而跟着变

工艺模板升了新版，维护界面看也是新版。可**新建**的批次套出来还是旧内容；
更奇怪的是有些**早就建好**的老批次，内容反而跟着新版变了。

### 现象三 · 主单的资料跑到子单名下

主单上传的图纸、工艺卡，会出现在它下属批次（子单）的资料列表里，还被标成是
**子单自己的**。财务按资料归属出归档清单时对不上数——一份主单的图纸被算成了子单的。

### 现象四 · 两张单共用一道工序，报工记录乱套

热处理是几张单共用的工序。忙时几个人同时用手持机报工，事后发现：有的记录
**跑到别的单上**去了，有的**多出来一模一样的一条**，还有**执行记录列表和这张单的
汇总数字对不上**。不忙的时候主观感觉很慢。

### 现象五 · 盘点做完，三个地方的数字对不上

盘点走完复核、审定、对账后，同一个物料能看出三个数：**台账余额、复核录入的实盘数
（换算过来）、对账汇总页**三边打架。此外海外仓按"克"复核、本部台账按"千克"记；
几个人同时复核同一张盘点单时，还出现过**有人录的数不见了、数对上了名字却记成别人**。

### 现象六 · 会签走乱：有的卡住、作废了还能往下走

单据要走四段会签（初审 → 中间两段并行 → 终审），中间能驳回重走、也能整单作废。
最近出现：并行两段几个人同时点，结果有的单**终审莫名批过了**，
也有**两段都批了却卡在终审**；被**驳回重走**的单只重批了初审就被当成"全批完"；
**整单作废**的单**还能继续走**；**看板显示的段位跟实际对不上**。
